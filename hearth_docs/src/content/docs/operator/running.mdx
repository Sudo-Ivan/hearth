Run these commands on the machine where you installed Hearth. The [command reference](/operator/hearthctl/) lists every flag for each one.

## Upgrade

```sh
hearthctl upgrade
```

This upgrades hearthctl and Hearth together. It backs up your instance before Hearth switches to the new version, and if the new version doesn't start, it goes back to the version you had before.

To see whether there's a new version without upgrading, run `hearthctl upgrade --check`.

If you installed Hearth before hearthctl existed, upgrade it with the current install script. It installs hearthctl and hands your instance to it with your data and settings as they are.

```sh
curl -fsSL https://hearth.dev/install.sh | sh -s -- --update --dir /path/to/your/instance
```

## Roll back

```sh
hearthctl rollback
```

This goes back to the version you had before your last upgrade and keeps your database as it is. To also restore the backup hearthctl made before the upgrade, add `--restore-database`.

## Back up and restore

```sh
hearthctl backup
```

This saves your settings, database and uploads in one file in the `backups` folder of your instance. Hearth pauses while it copies uploads. Keep a copy of your backups on another machine.

hearthctl keeps the newest 3 backups and deletes older ones after each backup, but it always keeps the one `hearthctl rollback` needs. To keep more, run `hearthctl backup keep 10`, or `hearthctl backup keep all` to keep every backup. To save backups on another drive, run `hearthctl backup location /mnt/backups/hearth`.

To put your instance back the way it was when a backup was made, find the file with `hearthctl backup list` and pass its path to `hearthctl restore`.

```sh
hearthctl restore /opt/hearth/backups/hearth-chat.example.com-20261105-120000.tar.zst
```

## Move to a new machine

Back up your instance on the old machine and copy the backup file to the new one. On the new machine, install hearthctl and restore the backup with one command, run from the folder you copied the backup to.

```sh
curl -fsSL https://hearth.dev/install.sh | sh -s -- restore hearth-chat.example.com-20261105-120000.tar.zst
```

Then change your domain's `A` record to the new machine's address.

## Manage people

Create an invite link that 10 people can use within a week.

```sh
hearthctl invites create --uses 10 --expires 7d
```

Choose who can create an account with `open`, `approval`, `invite` or `closed`.

```sh
hearthctl registration set approval
```

When registration needs approval, `hearthctl registration pending` lists the people waiting and `hearthctl registration approve <id>` approves one of them.

Make someone an admin.

```sh
hearthctl admins add alex
```

Ban an account and delete its messages.

```sh
hearthctl users ban spammer42 --reason spam --delete-messages
```

When someone has lost their password and can't reset it themselves, [create a reset link](/operator/sign-in/#lost-passwords) for them.

## Email and branding

Set up email for your instance, then send yourself a test email.

```sh
hearthctl email set
hearthctl email test you@example.com
```

Change your instance's name, color, logo or icon.

```sh
hearthctl branding set --name "Example Chat" --logo logo.png
```

You can also change email and branding in the admin panel, at your instance's address followed by `/admin`.

## Change a setting

```sh
hearthctl config list
```

This lists every setting with its value and a line of help, and says which settings restart Hearth when you change them. To change one, pass its name and the new value to `hearthctl config set`.

```sh
hearthctl config set <key> <value>
```

Each time hearthctl starts Hearth, it sizes memory limits, database connections and thread counts to the machine's memory and CPUs, so a resized machine needs no changes. The `memory.profile` setting pins a fixed size instead.

On a machine with little memory, `hearthctl config set FLUXER_API_EMBEDDED_WORKER true` runs background jobs inside the api service instead of a separate worker service. hearthctl then removes the worker and adds half of its memory limit to the api.

To add your own Caddy directives, such as extra routes or headers, put them in a `.caddy` file in the `caddy.d` folder of your instance. Hearth's Caddyfile loads every file there inside your site, and upgrades keep them. To use your own Caddyfile instead, mount it over `/etc/caddy/Caddyfile` on the `edge` service in a `custom.compose.yml` file in your instance folder.

## When something is wrong

```sh
hearthctl doctor
```

This checks your instance and the machine, and tells you how to fix each problem it finds. `hearthctl doctor --fix` fixes the problems hearthctl can fix safely.

`hearthctl status` shows whether each Hearth service is running, and `hearthctl logs` shows their logs.

## Manage it without hearthctl

To run your instance yourself with docker compose, run `hearthctl eject`. Hearth keeps running, and `hearthctl takeover` hands it back to hearthctl.

To upgrade Hearth while you manage it yourself, run `hearthctl takeover`, `hearthctl upgrade` and `hearthctl eject` one after the other. You can also [upgrade with the compose bundle](/operator/docker-compose/#upgrade) of the new version, the same way as an instance that never used hearthctl.
